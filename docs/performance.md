# Mocha 实机性能与验证

记录日期：2026-10-26～27。平台为 2 GiB 小米平板 Mocha、Tegra K1 / GK20A、ARMhf Debian、`6.12.111-moze.1-native-vde2`。测试通过普通 `mocha` 用户执行，桌面保持运行；工具没有调整频率或电压。单轮测量用于选择本机默认参数，不代表持续负载或其他机器的性能。

## v0.4.0：实验性 Q4 GPU

GPU 数学路径已打通，但当前不作为默认。上游 ggml 参考解量化与 GPU 对照覆盖 Q4_K、Q6_K、Q8_0、非紧密输入／输出步长、批量输入及超过 8 MiB 的分块边界，最大绝对误差约 `2.09e-7`。这是矩阵计算检查，不是完整模型逐 logit 等价认证。

最后一次实机复查使用 64 MiB 权重缓存、8 MiB 流式块、默认三线程、1024 上下文、温度 0、`-n 4`；桌面服务稳定后，通过 Wi-Fi 管理并临时阻止睡眠。未调整频率或电压。

| 模型 | GPU decode 速度 | 峰值子进程 RSS | 实际 Q4_K／Q6_K 调用 |
| --- | ---: | ---: | ---: |
| Llama 3.2 1B | 0.35 token/s | 844 MiB | 480／85 |
| Qwen2.5 1.5B | 0.19 token/s | 1130 MiB | 840／145 |

每行只有 3 次 decode eval，输出为短前缀，不能当作长时间吞吐。早期 `-n 16` 的流式候选也曾完成两款真实模型问答。当前路径明显存在上传、每算子同步和 CPU/GPU 交接开销，因此默认仍保留下方已经较快的 NEON CPU；没有把“GPU 执行成功”描述成“GPU 已加速”。

RSS 不含全部 GPU 缓冲，不能视为整机峰值；缓存、8 MiB 工作块及驱动另有开销。自动大缓存和单个超大缓存池均已撤回。诊断中发生过断连及用户确认的死机，需要重启恢复；没有持久化内核记录，根因未确定。最后短检查通过也不消除长稳风险，Q4 CUDA 仍标记为实验性。

## v0.3.0：大模型

2026-10-27，每款只执行一次短回答，默认三线程、1024 总上下文、32-token 微批次、温度 0、`-n 32`，遇结束标记提前停止。使用 llama.cpp b4514 的 ARMv7 NEON CPU 引擎与 Q4_K_M 权重，不使用 CUDA。

| 模型 | 权重文件 | 生成速度 | 峰值 RSS | 命令总耗时 |
| --- | ---: | ---: | ---: | ---: |
| Llama 3.2 1B Instruct | 770 MiB | 1.18 token/s | 842 MiB | 48.86 s |
| Qwen2.5 1.5B Instruct | 1066 MiB | 0.95 token/s | 1127 MiB | 52.53 s |

两款分别收到英文与中文的 Linux 简介指令，均返回对应语言的可读回答并正常退出。提示词、实际输出、引擎计时与峰值见 [实机记录](evidence/large-models-2026-10-27.json)。这不是知识准确度或模型能力评测。

生成速度采用 llama.cpp 的 decode eval 统计；命令总耗时还包括文件读取、初始化和预填充。RSS 由 Linux `getrusage(RUSAGE_CHILDREN)` 记录子进程峰值，包含映射的权重页，不代表整机内存占用；文件缓存可被回收。运行时还有桌面、内核、压缩交换等开销。未做内存填满或长时间压力测试，也没有为跑分改频率、电压。

## v0.2.0 CUDA 优化

同一提示词、Q8 权重、温度 0、重复惩罚 1，普通 mocha 用户，桌面持续运行，没有修改频率和电压。以下 Qwen 各行输出 16 token，完整文本 token 一致。数字为单轮短时测量，不能视为长期稳态保证。

| 路径 | 初始化 | 预填充 | 生成速度 | 引擎总耗时 |
| --- | ---: | ---: | ---: | ---: |
| 原 v0.1.0 引擎＋新 Runtime | 3.24 s | 5.12 s | 3.43 token/s | 12.74 s |
| 新 CUDA，512 线程 | 3.13 s | 4.12 s | 5.51 token/s | 9.97 s |
| 新 CUDA，1024 线程 | 3.24 s | 2.56 s | 7.75 token/s | 7.73 s |
| CPU＋GPU，GPU 90% 词表／CPU 4 线程 | 1.50 s | 7.89 s | 3.61 token/s | 13.54 s |
| CPU 4 线程，本轮连续测量末尾 | 0 s | 9.46 s | 2.40 token/s | 15.70 s |

新 CUDA 相对下方 v0.1.0 的 0.67 token/s 约提升 11.6 倍。此前 CPU 四线程约 3.09 token/s，本轮末尾约 2.40 token/s；温度、动态频率和后台桌面均会影响结果，跨轮比较只能作为参考。新默认选择 1024 线程 CUDA；协同模式可用于实验，目前没有超过纯 CUDA。

优化分为四部分：GK20A 使用 coherent 映射，避免缓存缓冲每次提交的全量 ARM cache 维护；缓存已验证的静态芯片身份，减少属性查询反复创建通道；四字节打包读取 Q8 权重，并将独立词表行分配到多个 CTA；先在 GPU 应用重复惩罚和控制 token 屏蔽，再选每个分区的 Top-k 候选供 CPU 采样。

空内核的稳态启动由约 1.29 s 降到约 0.00135 s，读取 4 字节从约 0.18 s 降到约 0.00021 s。完整词表为 607,744 字节；贪心只回传 512 字节候选，默认 Top-40 回传 20,480 字节。Top-k 候选不会修改温度、Top-p 或重复惩罚；大于 64 的 Top-k 及完整数值检查保留原始全量回传。

完整 CPU／CUDA 对照再次覆盖 6,229,376 个 logits，错误 0，最大绝对误差 0.00036239624，沿用原门限。候选路径另与完整 GPU 词表核对 Top-40／Top-64，并检查固定种子的采样输出一致。混合路径单独做 CPU 全词表对照。证据见 [优化记录](evidence/optimization-2026-10-26.json)。

## v0.1.0 Qwen2.5-0.5B-Instruct

源修订、Q8 权重与分词器哈希见 [模型清单](../models/qwen-inputs.json)。权重为 525,128,192 字节，GPU KV cache 为 6,291,456 字节；两个后端均使用相同权重。提示词是 `用一句话介绍Linux。`，完整 ChatML 模板共 34 token。温度 0，重复惩罚 1，线程数和线程块如下。

| 后端 | 输出 token | 引擎预填充 | 生成速度 | 命令总耗时 |
| --- | ---: | ---: | ---: | ---: |
| NEON CPU，3 线程 | 30，遇 EOS 停止 | 9.79 s | 2.52 token/s | 23.20 s |
| NEON CPU，4 线程 | 30，遇 EOS 停止 | 7.82 s | 3.09 token/s | 19.11 s |
| CUDA，512 线程块 | 16，上限截断 | 45.19 s | 0.64 token/s | 79.41 s |
| CUDA，1024 线程块 | 16，上限截断 | 43.86 s | 0.67 token/s | 77.15 s |

CPU 两种配置的输出完全相同，CUDA 两种配置与 CPU 的前 16 个 token 解码文本一致：

> Linux是一种开源的操作系统，以其开放性、灵活性和安全性著称，广泛应用于服务器、工作站、嵌入式设备以及企业环境。

命令总耗时包含 Python 分词、进程加载、CUDA 初始化、预填充和生成；CUDA 初始化约 7.8 s。生成速度按首个输出 token 后的后续 token 计时，不能把它当成端到端速度。预填充只更新 KV cache，跳过未被采样使用的最终词表投影。

CPU 默认 3 线程，给桌面留出余量；4 线程是本次实测更快的配置。CUDA 默认选实测稍快的 1024 线程块。当前 GPU 实现以每 token 一个持久 CTA 完成前向，尚未获得超过 NEON CPU 的速度；本发行版证明实际 CUDA 计算正确，不宣称 GPU 加速收益。

普通 CPU 模式进程 RSS 约 512 MiB。CUDA 普通模式在上传权重后丢弃文件映射页，进程结束前 RSS 约 11 MiB、进程峰值约 511 MiB；这**不包含全部 GPU 缓冲和页缓存**，不能理解为 GPU 模型只占 11 MiB 内存。显式 GPU 权重和 KV cache 合计约 507 MiB。

## CUDA 数值正确性

Qwen 使用相同提示词，逐步比较完整词表，覆盖 41 次前向、6,229,376 个 logits；每个元素按 `abs(gpu-cpu) <= 0.003 * (1 + abs(cpu))` 判断。结果无失败，最大绝对误差 `0.0003349781`。检查模式包含额外 CPU 前向及不跳过的词表投影，速度不能与普通模式比较。

该测试比较独立 CPU 和 CUDA 实现，另有分词器固定参考测试；它不是与 Transformers 全精度模型的逐层等价认证，也不是中文模型能力评测。

旧 Runtime 在第一个 token 就出现约 0.15 的 logit 误差。定位到 generic shared/local 地址窗口与大权重冲突后，修复 Runtime；修复前的失败未通过放宽误差门限处理。详情见 [Runtime 修复](cuda-runtime.md)。
